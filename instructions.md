# Build a Personal AI Anime Tutor

I want you to design and build a polished, extensible application that acts as my personal AI tutor.

The end goal is a **real-time 3D anime-style tutor living in a virtual environment**, capable of teaching me interactively rather than behaving like a normal chatbot.

I want you to take ownership of the technical design. **Do not blindly follow a prescribed architecture from this prompt.** Think through the problem, research appropriate technologies when useful, inspect the existing project/environment, and choose the architecture, libraries, frameworks, and implementation strategy that make the most sense.

I am giving you the desired experience and important constraints, not a step-by-step implementation plan.

---

## The End Goal

When the application is running, I want something that feels roughly like this:

A 3D anime-style female tutor is standing in a clean, minimal virtual environment.

Around her are floating windows that can be created, moved, resized, and closed.

I can type something like:

> "Teach me why the derivative of sin(x) is cos(x)."

She looks toward me/the input, processes the request, and then teaches me.

As she explains, she can dynamically create useful visual material around herself:

* equations
* graphs
* diagrams
* text
* images
* examples
* tables
* questions
* whiteboards
* other useful visualizations

She should naturally look toward whatever she is discussing.

If she is explaining an equation, she can look at the equation.

If she is explaining a graph, she can gesture toward it.

If she asks me a question, a small interactive window should appear where I can answer.

She should then evaluate my answer, respond to it, and continue the lesson.

The goal is for the experience to feel like **having an actual interactive virtual teacher**, not simply talking to an LLM with an anime model pasted on top.

# AI / LLM

I want the LLM to primarily run through an API.

My initial preference is DeepSeek because of its cost/performance, but **do not tightly couple the application to DeepSeek**.

Design the system so the underlying model/provider can be changed later.

The LLM should act as the tutor's reasoning and teaching brain.

It should be capable of:

* explaining concepts
* asking questions
* generating examples
* diagnosing misunderstandings
* adapting difficulty
* deciding when visual aids are useful
* creating visual material
* deciding what the character should do while explaining
* remembering relevant context
* using my uploaded syllabus/material
* tracking my progress

However, don't assume the LLM should directly control the application.

Design a safe interface between the AI and the application.

The AI should be able to request things such as:

* create a graph
* display an equation
* create a question
* display an image
* point toward something
* change expression
* look toward something
* perform a gesture

The application should interpret and validate those requests.

**Never execute arbitrary code generated by the LLM.**

# 3D Character

The tutor should be a real-time 3D character.

I want the character to feel alive without requiring me to manually animate every movement.

Use whatever combination of:

* procedural animation
* inverse kinematics
* rigging
* blendshapes
* facial animation
* look-at systems
* animation blending
* automatic lip sync
* other appropriate techniques

makes sense.

The character should be capable of things like:

* blinking
* breathing
* subtle idle movement
* looking at objects
* looking toward me
* turning her head naturally
* changing facial expressions
* speaking
* lip syncing
* pointing
* gesturing
* nodding
* reacting to answers
* showing emotions appropriate to the conversation

I care much more about **natural behavior** than having a huge number of hand-authored animations.

You should determine the best technical approach.

# GPU / Performance

I have an **RTX 3060 Ti with 8 GB VRAM**.

I want to use my GPU primarily for things where local GPU acceleration provides meaningful value, especially:

* real-time 3D rendering
* character animation/rendering
* high-quality local TTS
* other audiovisual processing where appropriate

I do **not** want to waste most of the VRAM running a large local LLM when an API can handle that job.

Design the system with VRAM limitations in mind.

The application should remain usable on my hardware.

Don't unnecessarily load huge models or expensive AI pipelines locally.

If something would consume significant VRAM, think about whether there is a better alternative.

The tutor should behave like a teacher.

She should not simply answer every question immediately.

Depending on the situation, she should be able to:

* explain intuitively
* derive formulas
* give examples
* ask me to predict something
* give me a problem
* ask follow-up questions
* provide hints
* identify misconceptions
* correct mistakes
* revisit weak concepts
* increase/decrease difficulty
* connect concepts together
* periodically check understanding

The exact tutoring methodology is up to you.

Design something that actually makes sense pedagogically.

# Important Engineering Principles

These are constraints, not a rigid implementation plan.

### 1. Think before coding

Inspect the existing repository and environment first.

Understand:

* operating system
* hardware
* available tools
* existing code
* existing dependencies
* current architecture

Then decide how to proceed.

### 2. Choose the technology yourself

Do not assume a particular engine or framework unless there is a good reason.

Consider the practical tradeoffs between appropriate technologies.

I care about the final experience and maintainability more than using a particular stack.

### 3. Don't overengineer

Use existing libraries and tools where appropriate.

Don't reinvent complex systems unnecessarily.

### 4. Keep systems modular

The tutor brain, character, rendering, audio, UI, education system, persistence, and LLM integration should be separable enough that they can evolve independently.

### 5. Treat AI output as untrusted

Validate structured AI commands.

Never execute arbitrary AI-generated code.

### 6. Keep performance in mind

The application should be designed around my RTX 3060 Ti 8 GB rather than assuming unlimited hardware.

### 7. Make reasonable decisions yourself

If something isn't specified, **make the decision yourself based on what best serves the end goal.**

Do not constantly stop and ask me about tiny implementation details.

Ask me only when a decision genuinely requires my input.

# Development Process

Build this incrementally.

Do not attempt to create the entire application in one enormous implementation.

Start with a sensible minimal vertical slice and gradually expand it.

At each stage:

1. Implement a coherent piece.
2. Build/run it.
3. Test it.
4. Inspect the result.
5. Fix important issues.
6. Commit the milestone to Git.
7. Continue.

Use meaningful commits.

For example:

```text
Initial project setup

Add 3D tutor scene

Add character controller

Add floating windows

Add LLM integration

Add tutor interaction system

Add speech system

Add interactive questions

Add syllabus system
```

These are examples, not a mandatory commit structure. Decide on the actual milestones yourself.

Do not make meaningless commits just to increase the commit count.

Never commit secrets, API keys, private documents, caches, or unnecessary generated files.

---

# Quality Bar

I don't want a fake prototype where everything is hard-coded just to demonstrate the concept.

Build the foundations properly enough that the project can continue growing.

At the same time, don't spend weeks engineering infrastructure before I can actually interact with the tutor.

Prefer **working vertical slices**.

For example, it is better to have:

3D character
+
input
+
LLM
+
speech
+
basic animation

working end-to-end,

than to have ten perfectly designed backend systems that cannot actually teach me anything.
